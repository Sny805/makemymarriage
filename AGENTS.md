## Project status tracking

- Read `docs/PROJECT_STATUS.md` before starting work that may affect project progress.
- After implementing or materially changing a major feature, update `docs/PROJECT_STATUS.md` before completing the task. Keep its current position, last-updated date, and milestone table accurate, and add or revise a milestone with the scope, status, date, validation actually performed, and remaining work.
- Do not create a separate milestone for routine fixes; update an existing entry only when the fix materially changes that feature's status or scope.
- Never record tests, reviews, deployment, or user acceptance that did not actually happen.
